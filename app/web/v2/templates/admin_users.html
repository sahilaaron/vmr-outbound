{# The account directory. Three things this page shows and one it deliberately does not. Shows: whether an account can sign in at all (state), whether it has a password yet, and when it last did sign in. Those three answer the questions an administrator actually has — "why can't Priya get in", "did I ever send her a link", "is this account still in use". Does not show: anything derived from the password itself. There is no hash on this page, no hash length, no "strength", and no way to read one back. The only password fact rendered is set / not set. The one-time link appears exactly once, on the response to the action that created it, and is gone from the server afterwards. The copy says so, because an administrator who assumes they can come back for it will hand somebody a dead end. Every form here is a POST, so the CSRF field is inserted at template-compile time by the extension registered in `app/core/auth/csrf.py`. There is no hidden field to write by hand here, and none to forget. #} {% extends "base.html" %} {% from "_ui.html" import tag, empty %} {% block content %}

People

Everyone who may sign in to this deployment. There is no public signup: an account exists because an administrator created it here. Disabling an account refuses its existing sessions on the next request, not at the next expiry.

{% if issued_link %}
One-time password link

Send this to the person out of band — a direct message or a phone call. It works once, expires in 24 hours, and will not be shown again. If you lose it, use “New password link” on their row to create another; the old one stops working. Issuing a link does not end that person's current session — if you are reacting to a suspected compromise, disable the account as well.
