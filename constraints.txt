# Pinned runtime dependency closure for VMR Outbound Agent deployments.
#
# WHY THIS FILE EXISTS
# --------------------
# pyproject.toml declares version *ranges*, which is right for development and
# wrong for deployment: two deploys of the same Git SHA could install different
# library versions and behave differently. `vmr-deploy` installs with
#
#     pip install --requirement constraints.txt
#     pip install --no-deps --editable .
#
# so the release directory gets exactly these versions.
#
# WHAT THIS IS NOT
# ----------------
# This is not a second package manager. The repository's canonical mechanism is
# pip + pyproject.toml (setuptools backend); a pip constraints file is that
# mechanism's own answer to reproducibility. Do not add uv/poetry/pipenv
# alongside it.
#
# SCOPE
# -----
# Runtime closure only - generated from `pip install .` in a clean virtualenv,
# deliberately WITHOUT the [dev] extra, because a staging release must not carry
# pytest/ruff/mypy. CI keeps installing `.[dev]` unconstrained, which is what
# makes CI able to notice an upstream break before a deployment inherits it.
#
# PLATFORM
# --------
# Generated on CPython 3.11 / Linux x86_64, which is the staging target.
# `psycopg-binary` is a platform wheel; regenerate on the target platform if
# that ever changes.
#
# Several pins here ship manylinux wheels, and their glibc floors differ from
# each other and move with every upstream release. No floor is written down here
# on purpose: a number in a comment goes stale silently, and a reader would act
# on it as though something had checked it. The check that cannot go stale is
# installation itself - pip refuses a wheel the platform cannot use, and
# `vmr-deploy` installs this closure and then import-checks the release before
# the symlink moves. So before changing the base image or the target platform,
# run the REGENERATING recipe below on that platform: an unusable wheel fails
# there, against the real thing, rather than against a comment.
#
# REGENERATING
#   python3.11 -m venv /tmp/lockvenv
#   /tmp/lockvenv/bin/pip install --upgrade pip setuptools wheel
#   /tmp/lockvenv/bin/pip install .
#   /tmp/lockvenv/bin/pip freeze --exclude-editable | grep -iv '^vmr-outbound' | sort -f
#
# Regenerate deliberately and review the diff. An unexplained version jump in a
# deployment constraints file is a supply-chain question, not a formality.
